# 27. Tile contamination and mutated crops

One of the [system guides](../Systems.md); read [How to use this document](../Systems.md#how-to-use-this-document) first. It builds on [section 22](22-FarmFields.md) (fields, tiles, the night, the look) and follows its rules wherever this guide says nothing.

**Status:** designed 2026-11-22 for [Roadmap.md, 4.2](../Roadmap.md#42-farming-depth) (the four contamination items together: the mutated crop, mutation of normal crops, a contamination level on each tile, a way to clean it); the code and the data are built (2026-11-22) as below. The cleaning crop's meshes, the crack look and `MI_Crop_Mutated` are in; `WBP_Hud`'s `TileText` waits for its hand step ([PlayTest.md](../PlayTest.md#2-pending-checks)), and a mutated crop shows its crop's ripe mesh tinted with `MI_Crop_Mutated` until mutated ripe meshes are made, if question 4 keeps mutation. It is built on the recommended options of the four contamination questions in [GameDesign.md, section 15](../GameDesign.md#15-open-questions), which @DunderGG hasn't answered yet, and on the texts the game designer decided in [GameDesign.md, section 6](../GameDesign.md#tiles). Every number is data, so a different answer is a data change, or a rule of a few lines where "If the design changes" below says so. Dirty water, storms, the thirsty look and the caretaker's reminder are later items; this guide leaves room for them and builds none of them.

**References:**

- Epic's "Instanced Static Mesh Component" page and the **PerInstanceCustomData** material node: the tile's contamination is one more custom data float on its soil instance, as its water is ([section 22](22-FarmFields.md)).
- Epic's "Developer Settings" page (`UDeveloperSettings`): the shared contamination numbers sit beside the water numbers in Vestige Farm Fields.
- Epic's `FRandomStream` (`Math/RandomStream.h`, an integer generator, the same on every platform), `FCrc::StrCrc32` (`Misc/Crc.h`) and `HashCombine` (`Templates/TypeHash.h`, documented as never changing for backward compatibility): a stream seeded from these gives the same answer on every run and every machine. `HashCombineFast` is documented as subject to change and only for hashes that stay in the running process, and `GetTypeHash(FName)` hashes the name's index in this process's name table. Neither feeds a repeatable roll, and the roll combines X and Y itself rather than through `GetTypeHash(FIntPoint)`.
- Lyra (`Source/LyraGame`) has no farming, soil or mutation; nothing is taken from it. What we keep is its rule that definitions are data assets and runtime state lives elsewhere: the crop says how it responds to contamination, the tile holds the level.

**How the parts fit:**

**Rules:**

- **Contamination is a whole-step level on every tile,** from 0 (clean) to the rules' `MaxLevel` (2: lightly, then heavily contaminated; [GameDesign.md, section 6](../GameDesign.md#tiles)). It is the glossary's tile contamination; code and data say "contamination", never "radiation", as the interface does.
   - **The data.** `FFarmTileState` has `int32 Contamination` (0 is clean), `GetContamination()` and `IsContaminated()` (above 0). It stays whatever the tile's state: grass, tilled, planted and withered tiles all keep it, and tilling, planting, watering, withering and clearing never change it. Only a cleaning harvest, a starting layout and developer tools change it. `bool SetContamination(int32 Level, int32 MaxLevel)` sets it clamped to 0 to `MaxLevel` and returns whether it changed; only `UFarmField` calls it.
   - **The shared numbers** are `FFarmContaminationRules`, a `USTRUCT` in `Farming/FarmContamination.h`: `int32 MaxLevel = 2` (`ClampMin = 1`) and `TArray<float> MutationChanceByLevel`, defaulting to `{0, 0.25, 0}` (index = level; a level past the array's end uses its last entry, an empty array means 0). `GetClamped` lifts `MaxLevel` to at least 1 and clamps each chance to 0 to 1; `float GetMutationChance(int32 Level) const` reads the array. `UFarmFieldSettings` holds one (`ContaminationRules`, category "Contamination", `GetContaminationRules()` returns it clamped), and `UFarmFieldSubsystem` passes it to `UFarmField::Initialize`, which takes `const FFarmContaminationRules& InContaminationRules` after the water rules, with no default: every caller, the tests' included, names the rules it means. The field keeps its copy (`GetContaminationRules()`) through a resize, as it does the water rules: `Resize` passes both copies to `Initialize`.
   - **Why on the tile, not a separate map or component:** contamination is per tile, saved with the tile, read by the tile's growth rule and drawn with the tile's soil; a parallel array would need its own resize, save and events kept in step. Why a level and not a float: the design has named steps the player learns, as water does, and an integer can't drift between "lightly" and "heavily".
- **A crop's response to contamination is its data,** replacing `ContaminationTolerance` (a float from 0 to 1 that nothing read, [CodeReview.md, L2](../CodeReview.md#low); a single "highest level it grows in" can't say "half speed on light soil"). `UFarmCropData` gains, in the category `Farming|Contamination`:
   - `TArray<int32> WateredNightsPerGrowthDay`, default `{1, 2, 0}`, index = the tile's level: how many watered nights make one growth day on that level, 0 meaning it doesn't grow there (and doesn't die). A level past the array's end uses the last entry. `int32 GetWateredNightsPerGrowthDay(int32 Level) const` answers, giving 1 for an empty array, so broken data grows as before rather than stalling every field. The three spring crops keep the C++ default (their assets never saved the property), the cleaning crop sets `{0, 1, 1}`.
   - `int32 MinPlantingContamination = 0` (`ClampMin = 0`): seeds of this crop are refused on a tile below it. The cleaning crop sets 1.
   - `int32 ContaminationCleanedPerHarvest = 0` (`ClampMin = 0`): the levels one harvest of this crop takes off its tile, not below 0. The cleaning crop sets 1, so a heavy tile takes two plantings.
   - `FPrimaryAssetId MutatedHarvestItemId` (`AllowedTypes = "VestigeItem"`): the item a mutated harvest gives, `Yield` times. Empty means the crop never mutates (`bool CanMutate() const`). The cleaning crop leaves it empty.
   - `TSoftObjectPtr<UStaticMesh> MutatedRipeMesh` (`AssetBundles = "Visuals"`): the mutated ripe look's shape; empty uses `RipeMesh`. `UStaticMesh* GetMutatedRipeMesh() const` gives the loaded mesh with that fallback, never loading.
   - `ContaminationTolerance` is removed. Saved crop assets that hold a value for it load without it (an unknown tagged property is skipped on load); the editor script that sets the new crop resaves the three spring crops so the stale value leaves the packages. No redirect: the meaning changed, so nothing maps across. This finishes the 4.0 item "Remove the data field nothing reads (`ContaminationTolerance`)" in the same commit, and the CodeReview L2 status line says so.
   - **Why per crop, not one shared slowdown in the settings:** [GameDesign.md, section 15](../GameDesign.md#15-open-questions) says each crop's tolerance is data so later crops can differ, and the cleaning crop is already the opposite of the others. **Why the mutation chance is shared, not per crop:** it is how mutagenic the soil is, tuned as one number for the whole slice; a crop opts out by having no mutated item. A per-crop chance is one field away if a crop needs one.
   - **Validation** (`UFarmCropData::IsDataValid`, errors): an empty `WateredNightsPerGrowthDay`; an entry below 0; a `MutatedHarvestItemId` that is of another type or names no item (the same check as `HarvestItemId`); a `MutatedRipeMesh` used by a growth stage; a crop that grows on no level from `MinPlantingContamination` up (`GetWateredNightsPerGrowthDay` is 0 for every index from it to the array's end, or the index is past the end and the last entry is 0: seeds that may only go where they can't grow). Validation doesn't read `UFarmFieldSettings`: `Content/` is below `Farming/` ([CodingGuidelines.md, section 14.1](../CodingGuidelines.md)), and a crop with fewer entries than levels is valid (the last entry repeats).
- **The night, in order.** Contamination changes no step that exists; it slots into the order [section 22](22-FarmFields.md) already fixes:
   1. **Withering**, on `OnSeasonStarted`, before the night (unchanged): a crop on any soil that doesn't grow in the new season withers.
   2. **Growth** (`FFarmTileState::AdvanceDay(int32 NightlyFall)`): a planted, unripe crop on a watered tile looks up `N = Crop->GetWateredNightsPerGrowthDay(Contamination)`. With `N` 0 nothing happens. Otherwise `WateredNights` goes up by one, and when it reaches `N` the crop grows one growth day and `WateredNights` goes back to 0. `N` 1 grows every watered night. A dry night changes nothing, so "every second watered night" means watered nights, as GameDesign.md says.
   3. **The water's fall** (unchanged), on every tile.
   4. **Mutation:** `AdvanceDay` now returns `true` when the crop became ripe tonight (it wasn't ripe before step 2 and is after). For such a tile, `UFarmField::AdvanceDay` calls `Tile.Mutate()` when the crop `CanMutate()`, the rules' `GetMutationChance(Contamination)` is above 0 and `FarmContamination::RollsMutation` says so. `bool FFarmTileState::Mutate()` sets `bMutated` on a ripe planted tile whose crop can mutate and returns false, changing nothing, on any other. So a crop rolls once in its life, on the night it ripens, on the level it ripened on.
   - Contamination itself doesn't change at night in the slice: there is no natural decay ([GameDesign.md, section 15](../GameDesign.md#15-open-questions), "Numbers"), so cleaning is always the player's work. Later sources fit after step 4 without a redesign: dirty water is `AddWater` plus a contamination step on the same tile at the time of watering; a storm's deposit is a dawn source after every field's night, through the subsystem event [section 22](22-FarmFields.md) already plans for the sprinkler. Neither is built now.
   - `UFarmField::AdvanceDay()` becomes `AdvanceDay(int32 Day, int32 MutationSeed)`; the subsystem's `AdvanceFields(int32 NewDay)` passes the new day and its seed. The field still broadcasts `OnTilesChanged` once after every tile.
   - `WateredNights` is reset to 0 by `Plant`, `Harvest` and `ClearWithered` and is 0 on any tile without a growing crop. It is saved, so a load doesn't lose half a growth day.
- **The mutation roll is repeatable,** so tests are exact and reloading the morning's save and sleeping again gives the same harvest. `bool FarmContamination::RollsMutation(int32 Seed, FName FieldId, const FIntPoint& Coordinates, int32 Day, float Chance)`: `Chance` at or below 0 is false and at or above 1 is true without a roll; otherwise it chains `HashCombine` over `uint32(Seed)`, `FCrc::StrCrc32(*FieldId.ToString().ToLower())` (lower-cased, since one field's `FName` may keep a different spelling in another run), `uint32(Coordinates.X)`, `uint32(Coordinates.Y)` and `uint32(Day)`, seeds an `FRandomStream` with the result and answers `GetFraction() < Chance`. No state, nothing to advance or save but the seed. A test pins one known input and its answer, so an engine change to any of these functions fails a test instead of silently changing every roll.
   - **The seed** is `UFarmFieldSubsystem`'s `int32 MutationSeed`: picked from `GetTypeHash(FGuid::NewGuid())` in `Initialize` and again in `StartNewGame`, so each new game rolls differently; saved in `FFarmFieldsSaveData::MutationSeed` and read back by `ReadSaveRecord` after its call to `StartNewGame` (which picks a fresh seed), never before (a record from before it has 0, a valid seed). `GetMutationSeed()` is public; `SetMutationSeedForTests` is test-only (`WITH_DEV_AUTOMATION_TESTS`), and field tests pass their own seed to `AdvanceDay` directly.
   - **Why not `FMath::FRand` or a stream kept on the field:** `FRand` can't be seeded per test without touching global state, and a stream that advances needs its position saved and would give a different crop after a reload replays the night. **Why the day is in the hash:** two crops ripening on one tile on different days roll independently.
- **A mutated crop is a ripe crop with another harvest and look.** `bool FFarmTileState::IsMutated() const` (`bMutated`, only ever true on a ripe planted tile). `FPrimaryAssetId FFarmTileState::GetHarvestItemId() const` is the crop's `MutatedHarvestItemId` when mutated, else its `HarvestItemId` (invalid without a crop): the one place that choice is made, used by the harvest ability for the item and for the room check. `Harvest`, `ClearWithered` and `Plant` clear `bMutated`. A mutated crop is otherwise ripe in every way: harvested on F, no wither (ripe crops don't), the same yield.
- **A cleaning harvest lowers its tile.** `FFarmTileState::Harvest()` lowers `Contamination` by the crop's `ContaminationCleanedPerHarvest`, not below 0, in the same call that empties the tile, so a harvest and its cleaning are one change with one `OnTileChanged`. The harvest ability copies the tile's `GetHarvestItemId()` and level **before** it calls `Field->Harvest` (its `State` pointer is the same tile, and the harvest clears `bMutated` and lowers the level), reads the level again after, and when it fell reports `Vestige.Feedback.Farm.Cleaned` ("The soil here is cleaner now."), or its child `Vestige.Feedback.Farm.Cleaned.Clean` ("The soil here is clean now.") when it reached 0 ([section 15](15-EffectsAndFeedback.md); a success the player is told about, as the well's "Can filled." is). A harvest has no message of its own; the cleaning line stands alone.
- **Seeds and contaminated soil** (`UFarmGameplayAbility_Plant::CanUseOn`), the first reason that applies, in this order: nothing to plant; out of season; no tile; withered (`Farm.ClearFirst`); can't plant (`Farm.CantPlant`); **below the crop's `MinPlantingContamination`, `Vestige.Feedback.Farm.NeedsContamination`** ("These seeds only grow in contaminated soil."); **the crop doesn't grow on the tile's level (`N = Crop->GetWateredNightsPerGrowthDay(State->GetContamination())` is 0), `Vestige.Feedback.Farm.TooContaminated`** ("This soil is too contaminated for these seeds to grow."); too late, as before but at the tile's rate (below). Both contamination reasons are refusals: no seed is used, nothing is remembered, and a repeat stays quiet, as for `Farm.CantPlant`.
   - **Why refuse on heavy soil, not warn and plant** (the reviewer's recommendation, built until @DunderGG answers, [GameDesign.md, section 15](../GameDesign.md#15-open-questions)): a crop there never grows and never dies, and no action pulls up an unripe crop, so a planting only loses the seed and blocks the tile from the cleaning crop until the season ends. **Switching back to a warning** is a few lines: report `Farm.TooContaminated` only when `!FarmingComponent->WasWarned(Farm.TooContaminated, CropId, Day)`, remember it in `OnPressRefused` as `Farm.TooLate` is, add "Press again to plant anyway." to the text, and skip the too-late check only when this tile's `N` is 0 and that warning is remembered for the crop today (never on another tile). The tag, its place in the order and the tests' setup stay.
   - **Too late counts the tile's rate.** `UFarmCropData::GetSeasonFit(const FVestigeCalendar& Calendar, int32 Day, int32 NightsPerGrowthDay = 1)` (not `WateredNightsPerGrowthDay`, the crop's own member, which it would shadow) sets `DaysToRipe = DaysToMature * NightsPerGrowthDay` (at least 1 for the multiplier; 0 never reaches it, the refusal above comes first) and compares that with the deadline, so a turnip on light soil needs 6 watered nights, not 3, and the warning and its `DaysToRipe` value say so. `CanUseOn` asks the fit without a rate for the out-of-season check, which comes before the tile is known (the season doesn't depend on the rate), and asks it again with the tile's `N` for the too-late check once the tile is known; the report's values come from that second fit. [Section 22](22-FarmFields.md)'s "The fit" says the same.
- **Where contamination starts.** A new game's field starts with its grid's layout: `AFarmGrid` has `TArray<FFarmContaminationArea> StartingContamination` (`EditAnywhere`, category "Farming"), each area `FIntPoint Min`, `FIntPoint Max` (inclusive corners, in tile coordinates) and `int32 Level`. `UFarmFieldSubsystem::FindOrAddField(FName FieldId, const FIntPoint& Size, TConstArrayView<FFarmContaminationArea> StartingContamination = {})` passes them to `UFarmField::ApplyContaminationAreas` **only when it makes the field**: a field restored from a save, or one that already exists when the map opens again, keeps its own tiles. Later areas overwrite earlier ones where they overlap; each tile's level is clamped by the field's rules; an area partly outside the field is cut to it, and one wholly outside is skipped with a `Warning` on `LogFarm`. The field logs one `Log` line with how many tiles started contaminated and broadcasts `OnTilesChanged` once.
   - **`L_Farm`'s layout** (the recommended bands, [GameDesign.md, section 15](../GameDesign.md#15-open-questions), question 2): on the 8 by 8 field, the two bands on the side nearest the farmhouse (the bed's side until a farmhouse exists) clean, the next four level 1, the two far ones level 2. The grid stands at yaw 0 with the bed west of column 0, so the bands are columns: 0 and 1 clean, `(Min=(2,0), Max=(5,7), Level=1)` and `(Min=(6,0), Max=(7,7), Level=2)`, set on `L_Farm`'s `BP_FarmGrid` instance by editor script (`SetUpContamination.py`, which logs `export_text()` after a reload), and `BP_FarmGrid`'s own default stays empty, so a new grid starts clean. Another answer to question 2 (one patch, other bands) is a change to these areas, no build.
   - **Why on the grid, not a new field data asset or the settings:** the layout belongs to one field in one level, as its size and ID do, and a mod's map places its own grid with its own areas. A field data asset (size, ID, layout, later soil types) is the better home once there are several fields or per-field rules; it is not worth a new primary asset type for one field. The settings are the same for every field, so they can't hold where one field is poisoned. **Why not random tiles:** question 2's option (c) is rejected by the designer, and random starts would need the seed in the layout rule too.
   - **Old saves:** `FFarmTileSaveData` gains `int32 Contamination = 0`, `int32 WateredNights = 0` and `bool bMutated = false`; a record without them loads every tile clean with no mutation and no partial night, the designer's rule for a save from before contamination. `FFarmFieldsSaveData` gains `int32 MutationSeed = 0`. `FFarmFieldsSaveData::Version` **stays 1**: every missing value defaults to a valid state, and raising it would drop the whole farm of a save from before ([section 1](01-Saving.md), and the water level's precedent). `Restore` gains the three values and the contamination cap: contamination clamped to 0 to `MaxLevel` on every tile, grass included; contamination is restored first, then `WateredNights` is kept only on a planted unripe tile, clamped to 0 to `FMath::Max(N - 1, 0)` with `N` the crop's nights for the restored level (so 0 where it doesn't grow); `bMutated` kept only on a ripe planted tile whose crop can mutate. Restore's parameter list is now long enough to take one `FFarmTileSaveData` plus the crop and the two caps instead (`Restore(const FFarmTileSaveData& Saved, const UFarmCropData* SavedCrop, int32 MaxWaterLevel, int32 MaxContaminationLevel)`), which the implementer does in the same change.
   - **Developer tools:** `UFarmField::SetContamination(const FIntPoint&, int32 Level)` (through `ChangeTile`, one `OnTileChanged`) and a cheat, `SetTileContamination X Y Level` in `UVestigeCheatManager`, which asks the field of the player's grid ([section 19](19-DebuggingAndCheats.md)): so a play-tester can try a level on any tile of an old save, and tests can set tiles without an area.
- **How the soil shows contamination: custom data 4,** on the soil part only ([section 22](22-FarmFields.md), the custom data table). `FarmTileLooks::NumCustomDataFloats` becomes 5; `ContaminationCustomDataIndex` is 4. `FFarmTilePartLook` gains `float Contamination` (0 to 1, the tile's level over `MaxContaminationLevel`, at least 1), set on the soil part for grass and tilled soil alike and left 0 on the crop part, so the crop placeholder (which shares `M_FarmPlaceholder`) never shows cracks. `GetLook` gains `int32 MaxContaminationLevel` after `MaxWaterLevel`; the meshes component passes its field's `GetContaminationRules().MaxLevel`. A fraction, not the level, so a changed cap needs no material change.
   - **The art:** a material function `MF_ContaminationCracks` (speckled cracks in the contamination cue, magenta per [GameDesign.md, section 15](../GameDesign.md#15-open-questions), the colour cues) reads custom data 4 (default 0) and masks a crack texture by it, sparse at 0.5 and dense at 1, nothing at 0, so the levels differ by shape and density as well as hue (colour-blind players). `M_FarmSoil` and `M_FarmPlaceholder` both use it, so grass (the placeholder slab) and tilled soil show it until grass has art of its own. It sits on top of the water's darkening, which stays a change in value: wet contaminated soil is darker soil with the same cracks. Both materials keep **Used with Instanced Static Meshes** saved.
   - **The placeholder colour doesn't change** with contamination: the cracks come from the material, which the placeholder already uses, and a second colour path would draw a magenta tint under the magenta cracks.
   - Every change of level reaches the soil instance as any tile change does: `OnTileChanged` updates its custom data in place (a harvest that cleans moves no instance of the soil), `OnTilesChanged` rebuilds.
- **The mutated ripe look.** For a mutated tile `GetLook` gives the crop part `Crop->GetMutatedRipeMesh()` (the crop's own ripe mesh when it has none) at full size, with `FFarmTileLookSettings::MutatedCropMaterial` on every slot, the same set mechanism as the withered look (one mesh, one material override; [section 22](22-FarmFields.md), "Why a material override, not custom data"). `MutatedCropMaterial` is `MI_Crop_Mutated`, an instance of `M_Crop` in the contamination cue, set on `BP_FarmGrid`'s look settings by editor script; empty keeps the mesh's own materials. The placeholder cylinder takes `FarmTileLooks::MutatedColor` (the cue's magenta) at its ripe height. One set per mutated crop kind, a few draw calls.
- **The HUD names the faced tile's level.** `AVestigeHUD` follows the pawn's `UFarmTargetingComponent::OnTargetTileChanged` and its grid's field's `OnTileChanged` (for the target tile only) and `OnTilesChanged`, and pushes `UVestigeHudWidget::SetTileText` into an optional `TileText` (`BindWidgetOptional`, added to `WBP_Hud` by hand as `MoneyText` was). The text is `AVestigeHUD::ContaminationLevelNames[Level]` (`TArray<FText>`, `EditDefaultsOnly`, defaults `{empty, "Lightly contaminated", "Heavily contaminated"}`, the last entry repeating past the end); an empty text, a clean tile and no target show nothing. Text in the HUD's Blueprint data, not the settings, so it localizes as asset text. Rebuilt only on those events, never per frame ([section 6](06-UserInterface.md)). Where the line sits on screen waits for the HUD's layout pass ([Roadmap.md, 4.6](../Roadmap.md#46-interface-and-input)); for now under the prompt.
   - **Binding lifetime.** The HUD binds the targeting component in `FollowPawn` (through its non-const `GetGrid()`, since binding the grid's `OnFieldReady` needs a non-const grid) and unbinds it in `StopFollowingPawn`. It binds a field only through the targeting component's grid: with no grid it shows nothing; with a grid whose field isn't ready (`IsFieldReady` false) it binds the grid's `OnFieldReady` once and binds the field then. It keeps a weak pointer to the bound field and, whenever the target changes, rebinds if the target's grid now shows another field. It unbinds the field (`RemoveAll(this)`) in `StopFollowingPawn` and `EndPlay`, because the field is the subsystem's and outlives the grid, the pawn and the HUD.
- **The cleaning crop and the mutated items are ordinary content** ([section 2](02-Content.md)), found by the catalogue with no list in code. Their IDs are functional and never shown, so the writer's names change none of them: the crop `Base.CleanupCrop` (`DA_Crop_CleanupCrop`), its harvest item `Base.CleanupCrop` and seeds `Base.CleanupCropSeeds` (`DA_Item_CleanupCrop`, `DA_Item_CleanupCropSeeds`), and `Base.MutatedTurnip`, `Base.MutatedPotato`, `Base.MutatedCabbage` (`DA_Item_Mutated*`). The numbers are the designer's proposal: 5 days to ripe, yield 1, the harvest sells for 30, seeds 15 from a fourth offer in `DA_Shop_Farm` and a fourth dispenser, `BP_ShopDispenser_CleanupCropSeeds`, in the service yard ([section 26](26-Shops.md)); each mutated item sells for twice its normal one. The cleaning crop's seasons are `Vestige.Season.Spring`. Its harvest isn't food: there is no eating yet, so nothing marks it; the food-safety item adds that flag ([GameDesign.md, section 6](../GameDesign.md#crops)).
- **Cost and logging.** Per tile per night: one array lookup and an integer step in the growth that already runs, and, only on a night a crop ripens on soil with a chance, one hash and one stream draw. Starting layout: once per new game, a loop over its areas' tiles. The redraw writes one more float per soil instance. Everything stays under the existing trace scopes (`UFarmField::AdvanceDay`, `UFarmFieldMeshesComponent`'s rebuild) and inside the new day's 100 ms ([Architecture.md, section 10](../Architecture.md#budget)); `ApplyContaminationAreas` gets a scope of its own. Nothing per frame or per hour; the HUD line is event-driven. Logging on `LogFarm`: the starting layout's count (`Log`), an area outside the field (`Warning`), each mutation (`Verbose`: "Base.Turnip at (3, 4) on field Base.Farm ripened mutated."). Refusals and the cleaning line reach the log through the feedback subsystem.
- **Mods.** A mod's crop sets its own response, cleaning and mutated item; a mod's map sets its grid's areas. `On Crop Harvested` still carries the crop and the tile, not whether it was mutated; the item is in the bag. A `bMutated` parameter comes when a mod or content Blueprint needs it ([Architecture.md, section 12](../Architecture.md#extension-points-today)).
- **If the design changes** (each a data change unless it says otherwise):
   - Question 1, four levels: `MaxLevel` 3, longer `WateredNightsPerGrowthDay` arrays and `MutationChanceByLevel`, a fourth HUD name, the material's density curve. Two levels: `MaxLevel` 1, arrays `{1, 0}`.
   - Question 2, another layout: `L_Farm`'s areas.
   - Question 3, a cleaning tool: a new tool ability calling `UFarmField::SetContamination(Tile, Level - 1)` (a design of its own); the cleaning crop's `ContaminationCleanedPerHarvest` back to 0 if it becomes food.

**Pitfalls:**

- Hashing an `FName` with `GetTypeHash`, or combining with `HashCombineFast` or `GetTypeHash(FIntPoint)`, for the roll: they may change between runs or engine versions, so a reloaded night would roll differently. Hash the lower-cased string (`FCrc::StrCrc32`) and combine with `HashCombine`.
- `Resize` calling `Initialize` without the field's contamination rules: the field would fall back to other numbers after any load whose field size differs from its grid. `Initialize` has no default for them.
- Setting the saved seed before `ReadSaveRecord`'s `StartNewGame`: the new game's seed replaces it.
- Reading the harvest item or the level through the tile pointer after `Field->Harvest`: the harvest has already cleared the mutation and lowered the level. Copy both first.
- Checking too late with the crop's `DaysToMature` alone: on light soil a crop needs twice the nights, so it would be let in and wither.
- Rolling on every ripe night instead of the night it ripens: a ripe crop left in the ground would get a new chance each night.
- Counting dry nights toward a slowed crop: "every second watered night" counts only nights it had water.
- Reading `UFarmFieldSettings` from `UFarmCropData` (validation included): `Content/` is below `Farming/`, and `Vestige.Architecture.IncludeDirection` fails.
- Applying the starting layout whenever a grid finds its field: reopening the map, or loading a save, would poison cleaned tiles again. Only a field the subsystem makes from a grid gets it.
- Writing contamination to the crop part's custom data: the crop placeholder shares `M_FarmPlaceholder` and would show cracks on the cylinder.
- Raising the save version for values whose defaults are valid: an older farm would be dropped whole.
- Inserting a mutated stage or tile state: mutation is a flag on a ripe tile, not a new `EFarmTileState`, so every planted check keeps working.
- Seeding the new-game seed from `FMath::Rand`: whether the global generator is seeded at startup isn't something to rely on; a new GUID's hash always differs.
- A crop asset that saved `ContaminationTolerance`: harmless on load, but resave it so the dead value leaves the package.
